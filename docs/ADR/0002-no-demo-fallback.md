# ADR-0002：移除演示检测器，权重缺失时显式失败

- 状态：已接受（2026-11-26）
- 背景：v1 为了证明链路可跑，内置了一个基于颜色规则的 `demo` 后端，
  并给所有数字打 `SELFTEST_ONLY` 标记。实践中这类数字极易被误抄进
  PPT / 简历 / 对外材料，造成「把演练当成绩」的风险。
- 决策：v2 **完全删除**合成检测器与合成数据生成器。所有推理路径只接受
  真实训练权重；权重不存在时：
  - CLI / `YoloDetector` 抛出带训练命令的 `DetectorError`；
  - `POST /api/v1/detect` 返回 **HTTP 503**，说明缺少哪个文件、该跑哪条命令；
  - `/health` 仍可用，并如实报告 `weights_available: false`。
- 理由：一个会「假装成功」的系统比一个明确失败的系统危险得多。
  服务可用性（健康检查、看板、配置接口）与推理正确性分开降级。
- 后果：
  - CI 不能依赖权重，因此单元测试使用 stub detector（duck typing），
    `tests/unit/test_pipeline.py` 明确这是测试替身，不产出任何对外指标；
  - 新克隆的仓库在跑完 `00 → 03` 之前，检测接口不可用，这是预期行为。
