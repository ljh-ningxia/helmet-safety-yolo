# 结论边界与下一步验证计划

> 页面唯一结论：**好的回答先给结论，再拿证据，最后承认适用范围。**
> 问答统一用「结论 → 证据 → 边界」三步，30 秒内讲完。

## 1. 当前可以说什么

| 结论 | 证据 | 边界 |
| --- | --- | --- |
| 系统六环节链路可端到端运行 | `run.py selftest` 输出、`run.py web` 看板 | 演练后端，不是 YOLO 推理 |
| 三组单变量 A/B 框架可复核 | `E*.json` 含冻结条件与环境指纹 | 数值来自合成数据 |
| 切片推理改变了召回与开销 | E1：Recall 0.450→0.825，FPS 30.99→3.37 | Precision 与 mAP 同时下降 |
| 冷却去重显著抑制重复上报 | E3：事件 120→1 | 不代表违规减少 |

## 2. 当前不能说什么

| 不能说 | 为什么 | 下一步 |
| --- | --- | --- |
| 「准确率提升 xx%」 | 无人工逐帧真值；检出框数量变化 ≠ 准确率 | 标注 ≥300 帧实拍测试集，重跑 `--backend yolo` |
| 「模型达到 SOTA / mAP 0.9+」 | 未做跨模型、跨数据集对照 | 引入公开基线，同条件复现 |
| 「系统实时稳定」 | 切片推理 FPS 3.37，未测 P95 时延与长视频 | TensorRT / 批处理优化 + P95 报告 |
| 「时序投票有效降低误报」 | E2 稳定场景事件 120→118，收益几乎为零 | 在真实误检分布上复验，若仍无收益则如实撤下该创新点 |
| 「现场事故率下降」 | 无真实部署与长期观测 | 与项目部合作做部署前后对照 |
| 「跨场景泛化良好」 | 只有单一合成场景 | 多工地、多光照、多机位测试 |

## 3. 未测项清单（答辩主动讲，比被问出来更好）

1. 夜间低照度 / 强逆光 / 雨雾 / 遮挡场景；
2. 长视频稳定计数与跨帧 ID 一致性；
3. 端到端 P50 / P95 / P99 时延；
4. 不同 GPU / CPU、TensorRT、批处理下的 FPS；
5. 冷却窗口 8 秒与现场处置节奏的匹配；
6. Webhook 在真实工单系统里的送达率；
7. 与人工巡查记录对照的漏报 / 误报统计。

## 4. 30 秒示范答复（可直接用于问答）

> **结论**：目前数据只能说明检测输出数量变化，不能写成准确率提升。
> **证据**：E1 里 B 的检出框从 360 涨到 708，但 Precision 0.500→0.476、mAP 0.6613→0.5632，FPS 还从 30.99 掉到 3.37；`src/metrics.py` 在无真值时直接拒绝输出 P/R/mAP。
> **边界**：测试集是固定 seed 的合成帧，没有人工逐帧真值；下一步会补标注和独立测试，并把 E2 在真实误检分布上重跑一遍。
