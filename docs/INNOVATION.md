# 三条可复核的创新陈述

> 页面唯一结论：**创新不是一个模型名称，而是有价值的问题改进。**

课程评分参照：创新 40% / 价值 30% / 实现 20% / 协作 10%。
「强主张」句式：针对【场景问题】在【模块】作【改动】，在【条件】下得到【真实结果】，目前仍有【尚未解决的限制】。

---

## 创新点 ① · 方法 / 算法：重叠切片推理应对远景小目标

- **问题**：高位俯拍画面中安全帽常仅 20×20 像素，整图缩放到 640 输入后被进一步压缩，远景目标漏检。
- **行动**：在**定位/检测**环节把整图一次推理改为带重叠的切片推理，逐片放大后预测，坐标回映原图，再做跨切片 NMS 融合；**不改模型权重、不改阈值**。代码 `src/tiling.py`。
- **结果**：同一 60 帧合成测试集、同一阈值、同一硬件下，Recall 0.450 → 0.825，检出框 360 → 708。
- **边界**：Precision 0.500 → 0.476、mAP@0.5 0.6613 → 0.5632、FPS 30.99 → 3.37。**召回是以误检和速度为代价换来的**，不声称「准确率提升」；合成数据结果不可外推。

## 创新点 ② · 工程 / 产品：跨帧时序投票抑制告警抖动

- **问题**：单帧误检或遮挡让告警忽明忽暗，现场人员对告警脱敏，报表中堆满重复事件。
- **行动**：在**判定**环节引入 IoU 轻量跨帧关联与连续 K 帧命中确认（K=3），miss_k 帧未命中释放；不引入额外跟踪模型。代码 `src/temporal.py`。
- **结果**：同一帧序列下告警事件 120 → 118，确认延迟增加 2 帧。
- **边界**：在目标稳定的合成场景中收益**几乎为零**，说明该改动价值依赖真实误检分布；**必须用实拍数据复验后才能主张有效**。这是当前最诚实的结论，也是明确的下一步。

## 创新点 ③ · 问题 / 产品：把检测结果接到可回溯的处置闭环

- **问题**：多数课程项目止步于「画框」，没有把结果送到「通讯/报表 → 业务动作」，事后无法追溯谁在何时被预警。
- **行动**：在**业务动作**环节补齐 L1/L2/L3 分级、8 秒冷却去重、证据快照、JSONL 事件台账与可选 Webhook（默认关闭，外部推送须本人确认）。代码 `src/alert.py`。
- **结果**：同一帧序列下事件条数 120 → 1，每条事件含时间、级别、轨迹 ID、置信度、框坐标、快照路径。
- **边界**：**事件变少不代表违规变少**，只代表重复上报被抑制；冷却窗口 8 秒是工程设定值，需按现场处置节奏标定。

## 与「算法之外五条路径」的对应

| 路径 | 本项目落点 |
| --- | --- |
| 问题 | 发现「检测完没有处置闭环」这一被忽略的场景 |
| 算法 | 切片推理改变检测输出 |
| 工程 | 时序投票降低抖动、冷却去重提升可靠性 |
| 产品 | 分级预警看板让现场更容易做决策 |
| 方法 | 三组单变量 A/B 让实验公平、可复核 |

## 三条不能写的话

1. ❌「使用 YOLOv8 完成安全帽检测」——弱表述，看不出问题、个人改动和验证条件。
2. ❌「准确率提升 97%」——无人工真值，检出框数量变化不能推断准确率。
3. ❌「系统实时稳定运行」——切片推理 FPS 3.37，未测 P95 时延，未做长视频稳定性验证。
